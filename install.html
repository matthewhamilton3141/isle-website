Install · 0.3.0 · universal

Four steps, one of them a terminal command.

Isle uses a private framework and AppleScript automation, which rules out the Mac App Store. It ships as a disk image you install yourself, and updates itself from there.

Download the disk image

Download and drag to Applications

Open the disk image and drag Isle into Applications. The build is universal and needs macOS 14 Sonoma or newer.

Clear the quarantine flag

Isle is code-signed, but not with a paid Apple Developer ID. macOS therefore quarantines the download and refuses to open it, usually reporting "Isle is damaged and can't be opened." That message describes the missing notarisation, not the file. One command clears it: 

$ xattr -dr com.apple.quarantine /Applications/Isle.app

Isle then opens normally. This is a one-time step — in-app updates are not quarantined, so it does not recur on later versions.

What that command actually does

com.apple.quarantine is an extended attribute macOS attaches to downloaded files. Gatekeeper reads it, finds no Developer ID signature and no notarisation ticket, and blocks the app. xattr -dr removes that attribute from the bundle, which tells macOS you vouch for the app yourself. Nothing about the app changes: the code is untouched and still signed, just not by an identity Apple has on file.

Run it only on software you trust, from a source you trust. Isle's full source is on GitHub, and a build you compile yourself never carries the flag.

If the disk image itself won't mount

The same flag, applied to the download:

$ xattr -dr com.apple.quarantine ~/Downloads/Isle-0.3.0.dmg

Choose a mode

First launch asks what Isle should be: Music, Claude Code, or Both. The choice is changeable at any time in Settings. Only the subsystems the active mode needs are started, so a Claude-only install never asks for Spotify permissions.

Grant permissions

In Music and Both modes, macOS prompts twice on first use.

PromptWhat it's forIf you decline
Automation → Spotify The transport controls, and the 1 Hz poll that owns the playback clock. The controls do nothing. Required for playback control.
Audio capture The Core Audio process tap that drives the waveform from Spotify's actual signal. Everything else keeps working; the waveform falls back to a procedural pattern rather than going flat.

Both can be changed later in System Settings → Privacy & Security, under Automation and under Microphone (or Audio Recording on newer macOS). Isle runs as a menu bar app with no Dock icon.

Troubleshooting

When it doesn't behave.

"Isle is damaged and can't be opened."

This is the quarantine flag, not a corrupt download. Run the xattr command from step 02.

Nothing appears in the notch

Isle has no Dock icon. Use Toggle Notch from the menu bar item. Isle also runs on Macs without a notch, drawn against the top edge of the display.

The waveform doesn't move

Audio capture requires macOS 14.4 or newer and permission to record audio. Re-enable Isle in System Settings → Privacy & Security, under Microphone or Audio Recording depending on the macOS version. Without it, the waveform runs a procedural pattern.

The controls do nothing

Automation permission for Spotify was declined. Re-enable Isle under System Settings → Privacy & Security → Automation.

The Claude glyph never changes

Confirm the hook is installed under Settings → Claude Code, and that ~/.claude/settings.json still contains the isle-cli entries. Sessions started before the hook was installed do not report.

Keeping it current

Updates

Isle checks for updates on launch and on demand. Each release is published as a disk image alongside a latest.json manifest signed with an Ed25519 key whose public half is compiled into the app, so an unsigned or mismatched update is rejected before installation.

Build from source

Locally built copies are never quarantined, so the xattr step does not apply.

$ git clone \
    https://github.com/matthewhamilton3141/isle.git
$ cd isle
# one-time: build the bundled now-playing bridge
$ ./scripts/build-mediaremote-adapter.sh
$ open Isle.xcodeproj  # then ⌘R
